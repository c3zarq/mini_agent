# T032 — Implementar limites e tratamento de falhas

**Status:** Concluída

## Objetivo

Fortalecer os mecanismos de controle do Agent, estabelecendo limites para o ciclo de execução e tratamento consistente de falhas durante a interação com o modelo e as ferramentas.

## Escopo

### 1. Limites de execução

- Manter o limite configurável de execução de ferramentas (`maxIterations`).
- Estabelecer um limite configurável para consultas ao Ollama (`maxModelCalls`).
- Impedir que o Agent ultrapasse os limites estabelecidos.
- Garantir o encerramento controlado quando um limite for atingido.
- Informar claramente qual limite provocou a interrupção.

### 2. Validação de entradas e respostas

- Validar os parâmetros recebidos pelo Agent antes de iniciar a execução.
- Verificar a estrutura da resposta recebida do Ollama.
- Rejeitar respostas incompatíveis com o protocolo JSON.
- Impedir a interpretação ou execução de operações provenientes de respostas inválidas.
- Preservar informações úteis sobre os erros de validação.

### 3. Tratamento de falhas

- Padronizar o retorno de erros ocorridos durante a execução.
- Tratar falhas de comunicação com o Ollama.
- Tratar respostas inválidas do modelo.
- Tratar falhas de execução das ferramentas.
- Tratar falhas de persistência no banco de dados.
- Garantir que exceções não interrompam o processo de maneira descontrolada.
- Evitar que o Agent informe sucesso quando uma etapa obrigatória falhar.

### 4. Integridade do ciclo

- Garantir que uma operação inválida nunca seja executada.
- Impedir novas consultas ao modelo após uma falha que determine o encerramento.
- Preservar a ordem das mensagens persistidas.
- Garantir que o encerramento por limite ou falha retorne informações suficientes para identificar o motivo.

## Fora de escopo

- Implementar novas ferramentas.
- Permitir criação, alteração ou exclusão automática de arquivos.
- Implementar aprovação humana de operações.
- Alterar o protocolo JSON definido na T027.
- Criar interface gráfica ou interface de usuário.
- Implementar mecanismos avançados de recuperação ou autorreparo do agente.

## Critérios de conclusão

- [ ] O Agent valida os parâmetros de entrada.
- [ ] Existe limite configurável para consultas ao Ollama.
- [ ] O limite de execução de ferramentas continua funcionando.
- [ ] O Agent encerra o ciclo ao atingir qualquer limite.
- [ ] Respostas incompatíveis com o protocolo são rejeitadas.
- [ ] Respostas inválidas não provocam execução de ferramentas.
- [ ] Falhas de comunicação são tratadas.
- [ ] Falhas de execução de ferramentas são tratadas.
- [ ] Falhas de persistência são tratadas.
- [ ] Exceções não provocam encerramento descontrolado.
- [ ] Os retornos de erro identificam a etapa e o motivo da falha.
- [ ] Os testes automatizados são aprovados.
- [ ] A suíte completa de testes continua aprovada.
- [ ] `git diff --check` não apresenta problemas.

## Resultado esperado

O Agent executa suas interações dentro de limites definidos, rejeita respostas inválidas e trata falhas de maneira controlada, preservando a integridade do histórico e do ciclo de execução.
