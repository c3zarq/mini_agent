# T047 — Executar testes integrados

**Status:** Em execução

## Objetivo

Validar o funcionamento integrado dos principais componentes do Mini Agent, verificando os fluxos reais de inicialização, conversação, consulta de arquivos, aprovação de alterações e persistência das informações.

## Escopo

### 1. Inicialização e gerenciamento de sessões

- Iniciar a aplicação utilizando os módulos reais.
- Selecionar um projeto previamente cadastrado.
- Recuperar uma sessão existente.
- Verificar a associação entre projeto, sessão e modelo.
- Encerrar a aplicação de maneira controlada.

### 2. Execução de ferramentas

**Modelos:** `qwen2.5-coder:0.5b` e testes integrados com respostas controladas.

| Verificação | Resultado |
|---|---|
| Solicitação de listagem de arquivos | Aprovada |
| Execução de `list_files` | Aprovada |
| Retorno do resultado ao contexto | Confirmado |
| Ciclo `list_files` seguido de resposta final com Ollama real | Aprovado |
| Leitura real de arquivo pelo módulo Files | Aprovada |
| Incorporação do resultado ao contexto em teste integrado | Aprovada |
| Ciclo completo `read_file` seguido de resposta final com Ollama real | Pendente |

**Observação:** o ciclo `list_files` foi concluído com inferência real do `qwen2.5-coder:0.5b`, após os ajustes nas instruções gerais. Os testes de leitura de arquivo confirmaram a integração entre Agent, Context, Tools, Files e Database, mas utilizaram respostas controladas. A validação completa de `read_file` com inferência real permanece pendente.

### 3. Execução integrada de ferramentas

- Solicitar ao modelo a listagem de arquivos do projeto.
- Solicitar a leitura de um arquivo específico.
- Verificar a execução das operações pelo módulo Tools.
- Confirmar que os resultados são incorporados ao contexto.
- Verificar se o modelo consegue produzir uma resposta final após receber os resultados.

### 4. Aprovação de operações

- Solicitar ao modelo uma proposta de criação de arquivo.
- Verificar a apresentação da proposta na CLI.
- Confirmar que a operação não é executada antes da autorização.
- Aprovar uma proposta e verificar a criação do arquivo.
- Rejeitar uma proposta e verificar a preservação do projeto.
- Verificar o comportamento diante de propostas inválidas.

### 5. Persistência e recuperação

- Confirmar o armazenamento das mensagens.
- Verificar a manutenção do histórico após encerrar a aplicação.
- Recuperar a sessão e consultar o histórico existente.
- Confirmar a associação correta das mensagens à sessão e ao projeto.

### 6. Segurança e tratamento de falhas

- Verificar o bloqueio de consultas a arquivos externos ao projeto autorizado.
- Verificar o bloqueio de propostas com caminhos inválidos.
- Confirmar que operações de gravação dependem de aprovação explícita.
- Verificar o comportamento diante de respostas inválidas do modelo.
- Verificar a continuidade ou interrupção controlada após falhas.

### 7. Registro dos resultados

- Registrar os fluxos integrados executados.
- Identificar os componentes envolvidos.
- Registrar os resultados observados.
- Identificar falhas e limitações.
- Encaminhar problemas identificados para avaliação na T050.

## Testes

- Verificar inicialização e recuperação de sessão com componentes reais.
- Verificar comunicação real com o Ollama.
- Verificar persistência de mensagens no SQLite.
- Verificar execução integrada de ferramentas de leitura.
- Verificar retorno dos resultados ao contexto do modelo.
- Verificar o fluxo de proposta, aprovação e rejeição.
- Verificar a recuperação do histórico após reinicialização.
- Verificar o bloqueio de operações externas ao diretório autorizado.
- Verificar o tratamento de respostas inválidas e falhas operacionais.

## Restrições

- Utilizar um diretório isolado para os testes.
- Preservar os projetos e arquivos reais do usuário.
- Não permitir acesso irrestrito ao sistema de arquivos.
- Não executar comandos arbitrários solicitados pelo modelo.
- Não permitir gravações sem aprovação explícita.
- Não considerar testes com dependências simuladas como comprovação de integração real.
- Não repetir testes anteriores sem justificativa.
- Registrar resultados observados, sem presumir sucesso.

## Critérios de aceitação

- Os principais fluxos da aplicação foram exercitados com componentes reais.
- A comunicação entre CLI, Agent, Context, Ollama, Tools e Database foi validada.
- A execução de ferramentas de leitura foi verificada.
- O fluxo de aprovação e rejeição foi validado.
- A persistência e a recuperação das conversas foram confirmadas.
- Os mecanismos de proteção do diretório autorizado foram verificados.
- As falhas identificadas estão registradas para tratamento.
- Os resultados permitem avançar para os experimentos com modelos pequenos na T048.

### 7. Protocolo e tratamento de falhas

Foram identificados dois problemas durante os testes com modelos pequenos:

1. Repetição de chamadas de ferramentas até atingir o limite de consultas.
2. Resposta JSON sintaticamente válida, mas incompatível com o protocolo, utilizando `type: response`.

A aplicação rejeitou corretamente a resposta incompatível, sem executar operações indevidas.

Os problemas foram encaminhados para avaliação na T050.
