# T039 — Implementar seleção de modelo

**Etapa:** P08 — Interface e acompanhamento do projeto  
**Status:** Concluída  
**Dependências:** T028, T038

## Objetivo

Implementar a seleção interativa de um modelo de linguagem entre os modelos disponíveis localmente no Ollama.

A seleção deverá ocorrer durante a inicialização da aplicação, antes do início da interface conversacional, permitindo que o usuário escolha qual modelo será utilizado pelo agente.

## Atividades

1. Analisar a implementação atual da comunicação com Ollama e a função `listModels()`.
2. Identificar o formato dos dados retornados pela listagem de modelos.
3. Implementar a obtenção dos modelos disponíveis localmente.
4. Apresentar os modelos encontrados em uma lista numerada no terminal.
5. Permitir que o usuário selecione um modelo pela identificação numérica.
6. Validar a entrada do usuário, rejeitando seleções inválidas.
7. Tratar situações em que nenhum modelo esteja disponível.
8. Tratar falhas de comunicação com Ollama durante a consulta dos modelos.
9. Encaminhar o modelo selecionado à interface conversacional.
10. Integrar a seleção ao fluxo de inicialização em `src/app.js`.
11. Implementar testes automatizados para listagem, seleção, validação e tratamento de falhas.
12. Verificar a compatibilidade com os módulos existentes.

## Critérios de conclusão

- A aplicação consulta os modelos disponíveis no Ollama.
- Os modelos encontrados são apresentados de forma identificável no terminal.
- O usuário consegue selecionar um modelo pela lista apresentada.
- A seleção é validada antes de iniciar a interface conversacional.
- Entradas inválidas não iniciam a conversa e permitem uma nova tentativa.
- A aplicação informa quando não existem modelos disponíveis.
- Falhas de comunicação com Ollama são tratadas sem encerramento inesperado.
- O modelo escolhido é encaminhado corretamente ao `runAgent()`.
- A seleção pode ser testada sem comunicação real com Ollama.
- Os testes automatizados específicos são aprovados.
- A suíte completa de testes continua aprovada.
- `git diff --check` não apresenta problemas.

## Restrições

- Utilizar os mecanismos de comunicação com Ollama já existentes no projeto.
- Utilizar recursos nativos do Node.js para a interação pelo terminal.
- Não adicionar dependências externas.
- Não implementar instalação, download ou remoção de modelos.
- Não implementar cadastro ou gerenciamento de projetos.
- Não implementar criação, seleção ou gerenciamento de sessões.
- Não implementar comandos especiais de terminal.
- Não implementar aprovação interativa de propostas.
- Não alterar a lógica de execução das operações do agente.
- Preservar a separação entre seleção do modelo, interface conversacional e execução do agente.
- Manter o identificador da sessão conforme o mecanismo de inicialização existente até a implementação da T041.

## Implementação

### Módulos criados

**`src/modelSelection.js`**

Implementa a seleção interativa de modelos disponíveis no Ollama.

Responsabilidades:
- Consultar os modelos por meio da função `listModels()`, recebida como dependência.
- Validar a resposta da consulta e a estrutura da lista.
- Informar quando não existem modelos disponíveis.
- Apresentar os modelos em uma lista numerada.
- Receber e validar a escolha do usuário.
- Permitir novas tentativas após entradas inválidas.
- Tratar falhas de consulta e encerramento da entrada sem seleção.
- Retornar o nome do modelo escolhido.

Utiliza `node:readline` para interação com o terminal e permite injeção de dependências para testes automatizados.

### Módulos modificados

**`src/app.js`**

Integra a seleção ao fluxo de inicialização da aplicação.

Novo fluxo:
1. Validar o identificador da sessão.
2. Consultar e selecionar um modelo disponível.
3. Validar o resultado da seleção.
4. Iniciar a interface conversacional com o modelo escolhido.
5. Encerrar a conexão com o banco de dados.

A função `main()` recebe as dependências de seleção e listagem de modelos, permitindo testar o fluxo sem comunicação real com Ollama.

A variável de ambiente `MINI_AGENT_MODEL` deixa de ser necessária para a inicialização, pois o modelo passa a ser escolhido interativamente. A variável `MINI_AGENT_SESSION_ID` permanece como mecanismo de identificação da sessão.

**`src/ollama.js`**

Não precisou de alterações. A função `listModels()` existente já fornece os dados necessários para a seleção.

**`src/cli.js` e `src/agent.js`**

Não precisaram de alterações. O modelo selecionado é encaminhado à CLI e utilizado pelo agente durante a execução.

### Persistência da sessão

O modelo escolhido é utilizado durante a execução, sem atualizar o campo `sessions.model` no banco de dados.

Essa decisão preserva o escopo da T039. A relação entre o modelo selecionado e o modelo persistido na sessão deverá ser considerada na implementação do gerenciamento de sessões, previsto para a T041.
