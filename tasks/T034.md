# T034 — Implementar aprovação de criação

**Etapa:** P07 — Criação e edição de arquivos  
**Status:** Concluída  
**Dependências:** T020 e T033

## Objetivo

Implementar o mecanismo pelo qual o usuário pode autorizar ou rejeitar explicitamente uma proposta de criação de arquivo apresentada pelo Agent.

A decisão deverá ser recebida e retornada de maneira estruturada, preservando os dados da proposta, sem executar a gravação no sistema de arquivos.

## Atividades

1. Analisar o retorno de propostas implementado em T033 e os mecanismos de validação de caminhos desenvolvidos em T020.
2. Implementar o fluxo de aprovação específico para propostas `create_file`.
3. Disponibilizar os dados da proposta para apresentação ao usuário, incluindo caminho, conteúdo e mensagem explicativa.
4. Permitir que o usuário aprove ou rejeite explicitamente a proposta.
5. Validar a decisão recebida, rejeitando respostas ausentes, inválidas ou ambíguas.
6. Validar o caminho de destino antes de disponibilizar a proposta para aprovação, respeitando o diretório autorizado e as restrições de segurança.
7. Impedir a aprovação de propostas cujo destino seja inválido, esteja fora do projeto ou corresponda a um arquivo existente.
8. Retornar o resultado da decisão de maneira estruturada, preservando a proposta original.
9. Implementar testes automatizados para os fluxos de aprovação, rejeição e tratamento de situações inválidas.

## Critérios de conclusão

- O mecanismo recebe propostas `create_file` produzidas pelo Agent.
- Os dados da proposta são preservados durante o fluxo de aprovação.
- O usuário consegue aprovar explicitamente uma proposta válida.
- O usuário consegue rejeitar explicitamente uma proposta válida.
- A ausência de decisão nunca é interpretada como aprovação.
- Respostas inválidas ou ambíguas são rejeitadas.
- Propostas com caminhos inválidos ou externos ao projeto não podem ser aprovadas.
- Propostas destinadas a arquivos existentes são rejeitadas.
- O resultado da decisão é retornado de maneira estruturada.
- A aprovação ou rejeição não executa gravações no sistema de arquivos.
- Nenhum arquivo existente é sobrescrito.
- Os testes automatizados específicos são aprovados.
- A suíte completa de testes continua aprovada.
- `git diff --check` não apresenta problemas.

## Restrições

- Não gravar arquivos no sistema de arquivos.
- Não sobrescrever arquivos existentes.
- Não executar automaticamente propostas aprovadas.
- Não interpretar ausência de resposta como autorização.
- Não permitir aprovação de caminhos externos ao diretório autorizado.
- Não implementar aprovação de propostas `replace_text`, pertencente às tarefas posteriores.
- Não implementar a interface interativa de terminal prevista para T044.
- Não implementar a gravação e o registro efetivo das operações, previstos para T037.
- Revalidar o destino no momento da gravação futura, evitando confiar exclusivamente na validação realizada durante a aprovação.
- Preservar o protocolo JSON e os mecanismos de segurança existentes.

## Implementação

- Criado `src/approval.js`, com validação de propostas `create_file`, destinos e decisões explícitas.
- Implementada a aprovação e rejeição sem execução de gravação.
- Bloqueados caminhos absolutos, destinos externos, links simbólicos externos e destinos existentes.
- Validado se o diretório pai é realmente um diretório.
