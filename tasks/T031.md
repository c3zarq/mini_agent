# T031 — Implementar ciclo controlado de execução

**Status:** Concluída

## Objetivo

Implementar o ciclo de execução do Agent, permitindo que o modelo solicite ferramentas de leitura, receba os resultados e realize novas consultas ao Ollama até produzir uma resposta final.

## Escopo

### 1. Integração dos módulos

Integrar os seguintes componentes:

- `agent.js`: coordenar o ciclo de execução.
- `context.js`: preparar o contexto e preservar os papéis originais das mensagens.
- `operations.js`: interpretar as respostas do modelo.
- `tools.js`: executar as ferramentas de leitura autorizadas.
- `database.js`: recuperar os dados da sessão e persistir as mensagens.

### 2. Ciclo de execução

O Agent deverá executar a seguinte sequência:

1. Preparar o contexto da conversa uma única vez.
2. Recuperar o projeto associado à sessão.
3. Persistir a mensagem atual do usuário.
4. Enviar as mensagens ao Ollama.
5. Interpretar a resposta recebida.
6. Persistir a resposta do modelo como `assistant`.
7. Verificar o tipo de resposta:
   - `final`: encerrar o ciclo e retornar a resposta.
   - `tool_call`: executar a ferramenta automática autorizada.
   - `proposal`: retornar a proposta sem executá-la.
8. Quando houver execução de ferramenta:
   - Persistir o resultado como `tool`.
   - Acrescentar as mensagens `assistant` e `tool` ao contexto em memória.
   - Consultar novamente o Ollama.
9. Repetir o ciclo até receber uma resposta final ou atingir o limite de iterações.

### 3. Persistência do histórico

O Agent será responsável por persistir as mensagens produzidas durante a interação.

Regras:

- A mensagem atual do usuário deverá ser persistida uma única vez.
- A preparação do contexto deverá ocorrer antes dessa persistência, evitando duplicação no histórico enviado ao modelo.
- Cada resposta válida do modelo deverá ser persistida com o papel `assistant`.
- Cada resultado de ferramenta deverá ser persistido com o papel `tool`.
- O conteúdo das mensagens deverá ser armazenado como texto JSON quando representar objetos.
- Falhas de execução retornadas pelas ferramentas também deverão ser registradas como mensagens `tool`.

### 4. Preservação dos papéis

A função `buildContext()` deverá preservar os papéis originais recuperados do banco.

Mensagens com papel `tool` deverão continuar sendo identificadas como `tool`, sem conversão para `assistant`.

### 5. Limite do ciclo

Implementar um limite básico e configurável de iterações para impedir ciclos infinitos.

Ao atingir o limite, o Agent deverá encerrar a execução e retornar um resultado indicando que o limite foi alcançado.

O tratamento mais abrangente de limites e falhas permanece reservado à T032.

### 6. Tratamento de propostas

Respostas do tipo `proposal` representam operações que exigem aprovação.

O Agent deverá:

- Retornar a proposta ao chamador.
- Não executar a operação.
- Preservar a resposta no histórico como `assistant`.

O mecanismo de aprovação humana não faz parte desta tarefa.

## Fora do escopo

- Implementar aprovação humana de operações.
- Executar operações de criação, alteração ou exclusão de arquivos.
- Criar novas ferramentas de leitura.
- Alterar o protocolo JSON.
- Implementar mecanismos abrangentes de controle de recursos.
- Implementar políticas avançadas de recuperação de erros.
- Criar interface de usuário para interação com o Agent.

## Critérios de conclusão

- [x] O Agent prepara o contexto uma única vez por interação.
- [x] O Agent recupera o projeto associado à sessão.
- [x] A mensagem do usuário é persistida sem duplicação.
- [x] O Agent interpreta as respostas do modelo.
- [x] O Agent executa ferramentas automáticas autorizadas.
- [x] O resultado de cada ferramenta é devolvido ao modelo.
- [x] O Agent permite consultas sucessivas ao Ollama.
- [x] O Agent encerra o ciclo ao receber uma resposta `final`.
- [x] Propostas não são executadas automaticamente.
- [x] Mensagens `assistant` e `tool` são preservadas no histórico.
- [x] Existe um limite básico de iterações.
- [x] Os testes automatizados são aprovados.
- [x] A suíte completa de testes continua aprovada.

## Testes previstos

1. Executar uma interação simples com resposta final.
2. Executar uma ferramenta e receber uma resposta final.
3. Executar duas ou mais ferramentas sucessivamente.
4. Verificar a ordem das mensagens `assistant` e `tool`.
5. Verificar a persistência das mensagens da interação.
6. Verificar que a mensagem do usuário não é duplicada.
7. Verificar que propostas não são executadas.
8. Verificar o tratamento de falhas retornadas pelas ferramentas.
9. Verificar o encerramento ao atingir o limite de iterações.
10. Verificar o comportamento diante de falhas de persistência.
11. Preservar os testes anteriores do Agent.
